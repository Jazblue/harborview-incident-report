Executive Summary

A ransomware attack encrypted 4,892 files on the firm's primary file server. The attacker gained access using credentials for a local service account (svc-techconnect) that were stored in plaintext on a stolen IT technician laptop. The attack included data exfiltration (double extortion). All evidence points to a single root cause: plaintext credential storage on a portable device that left the premises. No additional lateral movement was detected. Windows Defender did not detect the custom ransomware payload.

Root Cause Chain

  1. Initial Access: IT provider's laptop was stolen from a vehicle on Friday afternoon. The laptop was left logged in with the svc-techconnect password saved in a plaintext file on the desktop.
  2. Credential Theft: Attacker accessed the stolen laptop remotely via TeamViewer (pre-installed and auto-starting), located the password file, and extracted the current credentials for svc-techconnect.
  3. Lateral Movement: Attacker used the credentials to log directly into FILE-SRV-01 from a DigitalOcean VPN/proxy at 02:47 AM Sunday.
  4. Execution: Attacker manually executed a PowerShell ransomware script (TechConnect_Update.ps1) that renamed 4,892 files, dropped a ransom note, deleted all Shadow Copies, and self-deleted.
  5. Exfiltration: Attacker compressed and uploaded 500MB of sensitive client data to a Tor hidden service before encrypting. Double extortion.
  6. Cover Tracks: Deleted the PowerShell script and the scheduled task used as a persistence mechanism.

Key Findings

  • Double extortion confirmed: 500MB of client data was exfiltrated before encryption. The attacker can leak data even if backups are restored.
  • Custom ransomware payload: Not a known strain. Written in PowerShell, self-deleting, executed in memory. Windows Defender did not detect it.
  • SIEM blind spots: Mass-file-modification threshold was set to 5,000 files; attacker stopped at 4,892. Shadow-copy-deletion alerts were downgraded for service accounts.
  • No lateral movement: Attacker went directly for the file server using compromised credentials.
  • RMM not compromised: TechConnect Pro cloud console showed no anomalous activity. The attacker operated entirely outside the RMM channel.
  • TLS inspection saved evidence: The company's TLS-inspecting proxy captured the Tor hidden service certificate and confirmed exfiltration to harborviewdecrypt.onion.
  • Antivirus evasion: The custom PowerShell script ran in memory, used ErrorActionPreference SilentlyContinue, and self-deleted. Windows Defender had no signatures for this payload.

Lessons Learned

  • Never store credentials in plaintext files on portable devices. Use a password manager with MFA.
  • Report device theft immediately. The 3-hour delay gave the attacker a 60-hour window.
  • SIEM rules must not be account-aware for destructive actions. Shadow copy deletion by a service account is still highly suspicious.
  • RMM tools create a single point of failure. Compromise of the service account exposes the entire managed fleet.
  • Double extortion is now standard. Exfiltration occurred before encryption. Data breach notification is required regardless of backup restoration.
  • PowerShell ransomware is hard to detect without AMSI enforcement and EDR. Defender alone is insufficient for server workloads.
  • Service accounts should not be interactive. svc-techconnect was used for remote interactive logins, which is not its intended purpose. Implement Just Enough Administration (JEA) and Privileged Access Management (PAM).
